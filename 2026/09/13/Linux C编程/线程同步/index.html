线程同步

竞态条件

在并发系统中，多个线程同时访问并尝试修改同一块共享资源时，最终的执行结果严重依赖于线程被操作系统调度的微观时序。由于操作系统调度器的调度是不可预测的，导致结果呈现随机性

互斥锁

相关详情

为单一占有模式，加锁解锁的开销低，适用于写操作频繁的场景

不管线程进来是只读数据还是修改数据，一律“一次只放一个人进入”。如果 100 个线程都只是想读取同一个变量，互斥锁也会让他们乖乖排队，效率低下

初始化

  1. int pthread_mutex_init(pthread_mutex_t* mutex, const pthread_mutexattr_t* attr);

    在内存中开辟锁的状态标记，并将锁的状态设为未上锁状态，可以通过attr设置锁的属性，NULL为默认

  2. pthread_mutex_t … = PTHREAD_MUTEX_INITIALIZER;

    不用显示调用pthread_mutex_init()函数，直接初始化并将锁的状态标记为未锁定

死等加锁

int pthread_mutex_lock(pthread_mutex_t* mutex);

检查锁的状态，如果为空闲赋予许可，否则该线程被剥夺CPU执行权，进入睡眠(阻塞状态)直到占有锁结束使用。一旦锁的线程崩溃、忘记解锁、产生死锁、线程将会无限挂起

试探性加锁

int pthread_mutex_trylock(pthread_mutex_t* mutex, const struct timespec abstime);

如果锁为空闲，直接加锁并返回0。如果锁被占用，立刻返回错误码

限时等待加锁

int pthread_mutex_timedlock(pthread_mutex_t* mutex, const struct timespec* abstime)

abstime为绝对的时间戳(2026-09-12 20:00:00)。如果超过设定的时间返回错误码

解锁

int pthread_mutex_unlock(pthread_mutex_t* mutex);

将锁的状态重置为未锁定

销毁

int pthread_nutex_destory(pthread_mutex_t* mutex);

清理互斥锁占用的系统资源(无线程需求)，若该锁正被使用或有线程等待，销毁会报错

读写锁

相关详情

为双模式分立，读锁共享，写锁独占，内部维护读计数器与等待队列，锁维护开销高，适用于读多写少的场景

把访问权限区分对待。只要没有人在写数据，100 个读线程可以同时进入临界区并发读取；只有当有人要修改数据（加写锁）时，才会阻断其他所有读和写的操作

API调用

初始化(统一)

  1. int pthread_rwlock_init(pthread_rwlock_t* rwlock, const pthrad_rwlockattr_t attr)

    动态初始化锁

  2. pthread_rwlock_t ... = PTHREAD_RWLOCK_INITIALIZER;

    静态初始化锁

读模式加锁

用于只读访问共享资源的场景，允许多个线程同时加锁成功

死等读锁

int pthread_rwlock_tryrdlock(pthread_rwlock_t* rwlock);

尝试获取读锁。如果当前锁被其他线程持有写锁，当前线程卡住（阻塞）进入睡眠，直到写锁被释放；如果当前无锁，或只有其他线程持有读锁，立刻加锁成功

试探性读锁

int pthread_rwlock_tryrdlock(pthread_rwlock_t* rwlock);

尝试获取读锁。不管成功与否绝不阻塞。如果当前有写锁占着，函数立刻返回错误码EBUSY

限时读锁

int pthread_rwlock_timedrdlock(pthread_rwlock_t* rwlock, const struct timespec abstime);

尝试获取读锁，若被写锁阻挡则睡着等待，但最多只等到指定的绝对时间 abstime。超时未拿到锁则唤醒返回ETIMEDOUT

写模式加锁

用于修改共享资源的场景，具有排他性，同一时间只允许一个线程成功

死等写锁

int pthread_rwlock_wrlock(pthread_rwlock_t *rwlock);

尝试获取写锁。只有当锁处于既没有读锁，也没有写锁的全空闲状态时，才能加锁成功。只要当前有任何人在读或写，当前线程立刻卡住（阻塞）进入睡眠

试探性写锁

int pthread_rwlock_trywrlock(pthread_rwlock_t *rwlock);

尝试获取写锁。若当前有任何锁（读锁或写锁）存在，立刻返回 EBUSY，绝不上锁等待

限时写锁

int pthread_rwlock_timedwrlock(pthread_rwlock_t rwlock,const struct timespec abstime);

尝试获取写锁，若当前被其他锁卡住，最多等待到 abstime 指定的绝对时间点，超时返回ETIMEDOUT

解锁函数(统一)

int pthread_rwlock_unlock(pthread_rwlock_t* rwlock);

自动识别当前线程加的是读锁还是写锁并做相应的内部计数清理

销毁读写锁(统一)

int pthread_rwlock_destroy(pthread_rwlock_t* rwlock);

销毁读写锁并释放资源。销毁前锁必须处于完全解开状态且无线程等待

写饥饿机制

详情

由于读线程频繁且连续地获取读锁，导致获取写锁的线程被长期甚至无期限地阻塞，无法获得CPU运行机会的现象。容易造成其他读线程一直在读取过期的脏数据，且大量卡在pthread_rwlock_wrlock处的写线程无法释放，占用系统线程资源和栈空间

解决代码

  1. 设置读写锁属性，显式将策略指定为写优先
  1. 使用互斥锁替代

互斥锁拓展 – 条件变量pthread_cond_t

restrict关键字 – 前置知识

int* restrict a

对编译器确保在当前作用域内，该指针是访问其所指向数据的唯一途径。CPU执行指令的速度快于RAM内存的访问速度，当CPU和编译器将数据保存在寄存器中处理，而非频繁读写内存时，能够极大优化性能。如果没有restrict涉及指针，每次都需要重新读取指针的数据，使用restrict保证地址不重复后实现一次读取，多次使用。

关于互斥锁拓展的API操作

pthread_cond_wait死等条件触发

int pthread_cond_wait(pthread_cond_t* restrict cond, pthread_mutex_t* restrict mutex);

将传入的mutex解锁，将当前线程加入到cond等待队列中，让出CPU执行权，当被signal或broadcast唤醒后，函数不会立刻返回，而是尝试重新对mutex加锁，只有成功重新拿到mutex后，pthread_cond_wait才会返回

pthread_cond_timedwait限时等待条件触发

int pthread_cond_timedwait(pthread_cond_t* restrict cond, pthread_mutex_t* restric mutex, const struct timespec* restrict abstime);

对比pthread_cond_wait多了一个绝对时间超时参数abstime，若超时未成功，该函数会夺取mutex锁成功后返回

pthread_cond_signal唤醒至少一个等待线程

int pthread_cond_signal(pthread_cond_t* cond);

唤醒在cond等待队列中的至少一个线程，如果多个线程在cond等待队列，通常按照FIFO或优先级进行唤醒

pthread_cond_broadcast广播唤醒所有等待线程

int pthread_cond_broadcast(pthread_cond_t* cond);
唤醒在cond等待队列中的所有线程，被唤醒的若干线程会竞争同一个互斥锁，拿到锁的继续执行，没拿到的排队等锁

关于pthrad_cond_t条件变量的相关知识

pthread_cond_init初始化

  1. 动态初始化
    int pthrad_cond_init(phtread_cond_t* restrict cond, const pthread_condattr_t* restrict attr);

attr为cond的属性，默认设为NULL

  1. 静态初始化
    pthread_cond_t cond = PTHREAD_COND_INITIALIZER;

pthread_cond_destroy销毁

int pthread_cond_destroy(pthread_cond_t* cond);

销毁条件变量，销毁时不能有任何线程正在该条件变量上等待

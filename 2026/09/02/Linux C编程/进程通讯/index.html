进程通讯

必要性与通信方式

必要性

默认情况下，每个进程拥有独立的虚拟地址空间(mm_struct)和文件描述符表(files_struct)，一个进程无法直接修改另一个进程的内存数据，两个进程间数据难以交互

通信方式

  1. Unix Domain Socket IPC
  2. 管道(有名管道、无名管道)
  3. 共享内存
  4. 消息队列
  5. 信号量

管道 – 内核(小)

匿名管道(父子进程、兄弟进程…) – pipe

介绍

位于内核的一块缓冲区，用于进程间通信。创建匿名管道的系统调用为pipe。

注意

  1. 一个管道只能实现单向通信，如父读子写，假如要实现父写子读则需要另开一个管道。
  2. 进程间通信必须使用同一个管道的文件描述符，fork创建的子进程会继承父进程的文件描述符，故一般pipe(pipefd)在fork之前，实现统一管道文件描述符

示例函数 – 创建

int pipe(int pipefd[2]);
pipefd为用于返回指向管道两端的两个文件描述符，pipegd[0]指向管道的读端，pipefd[1]指向管道的写端；成功返回0，不成功返回-1并且pipefd不会改变

有名管道(任意进程) – fifo

示例函数 – 创建

int mkfifo(const char* pathname, mode_t mode);

成功返回0，失败返回-1；mode指定管道文件的基础访问权限，即rwx权限0664；pathname为指定的有名管道的存储路径(推荐存放于/tmp/…路径下)

通过read与write实现数据传输，一方设置为O_WRONLY另一方为O_RDONLY

示例函数 – 清理

int unlink(const char* pathname);

pathname为需要删除的文件或管道路径，成功返回0，失败返回-1

区别

  1. 有名管道
    有名管道在文件系统中拥有一个真实的节点，可以通过路径访问，不限定于父子进程、兄弟进程，任意两个不相关的独立进程均可通信；同时持久存在于文件系统，不随进程消亡而消失

  2. 匿名管道
    匿名管道只存在于内核内存中，没有文件名，不存储在磁盘和文件系统中；其数据传递依赖于父子进程、兄弟进程等(必须通过fork()继承fd)；随进程消亡，当所有持有该fd的进程退出后，管道被内核自动销毁

共享内存 – 内存(大)

概念与优势

是Linux所有IPC(进程间通信)机制中效率最高的一种。传统IPC(管道、消息队列…)的数据传输需要经过四次数据拷贝和多次用户态/内核态的切换，如：

  1. 进程A用户缓冲区->进程A内核缓冲区
  2. 内核缓冲区->IPC管道/消息队列
  3. IPC管道/消息队列->进程B内核缓冲区
  4. 进程B内核缓冲区->进程B用户缓冲区

而共享内存直接将同一块物理内存映射到不同进程的虚拟地址空间中

示例函数 – 创建对象

int shm_open(const char* name, int oflag, mode_t mode);

  1. name为共享内存对象的名称，必须以斜杠开头(如”/my_shm”)，该对象会被挂载在Linux的/dev/shm内存文件系统中
  2. oflag标志位，决定打开方式，如O_RDONLY、O_RDWR、O_CREAT(若对象不存在则创建)、O_EXCL(配合O_CREAT使用，若对象已存在则直接报错)
  3. mode为创建对象时的权限，如0664
  4. 成功返回对应的文件描述符，失败返回-1

示例函数 – 设置内存

通过shm_open创建出来的共享内存对象，其初始大小为0字节，必须通过ftruncate为其分配指定的物理内存空间

int ftruncate(int fd, off_t length):

  1. fd为shm_open创建返回的文件描述符
  2. length为设置的字节大小
  3. 成功返回0，失败返回-1

示例函数 – 内存映射

将内核管理的共享内存空间直接映射到当前进程的虚拟地址空间(堆和栈之间的内存映射区)，从而通过类指针读写该内存

void* mmap(void* addr, size_t lenght, int prot, int flags, int fd, off_t offset);

  1. addr为映射过去的虚拟地址空间的起始地址，建议NULL让内核自动选择
  2. length为要映射的内存长度，通常与ftruncate设定的长度保持一致
  3. prot内存保护权限(必须与shm_open的打开模式相匹配)，如PROT_READ允许读取、PROT_WRITE允许写入
  4. flags控制映射行为，MAP_SHARED其他映射该内存的进程可见对该内存的修改，MAP_PRIVATE对内存的修改是私有的，修改不会同步给其他进程
  5. fd由shm_open返回的文件描述符
  6. offset映射的偏移量，IPC中通常为0
  7. 成功返回映射区首地址指针，失败返回MAP_FAILED

示例函数 – 解除内存映射

将之前由mmap映射的地址空间断开
int munmap(void* adddr, size_t length);

  1. addr为mmap返回的起始指针
  2. length为映射的字节长度
  3. 进程退出时内核会自动调用munmap，但显式调用是良好的C语言资源管理习惯

示例函数 – 清除共享内存对象

int shm_unlink(const char* name);

调用shm_unlink后，新的进程无法再通过shm_open打开，但已经mmap映射成功的进程依然可以继续读写通信，直到所有映射该内存的进程都彻底接触映射/退出后，内核才会真正释放该物理内存

消息队列

消息队列结构体/API

struct mq_attr

struct timespec

clock_gettime()

获取以struct timespec形式表示的clockid指定的时钟

int clock_gettime(clockid_t clockid, struct timespec* tp);

  1. clockid为特定的始终标识符，常用的是CLOCK_REALTIME表示当前真实时间的始终
  2. tp用于接收时间信息的timespec结构体的地址(将时间传进该地址)
  3. 成功返回0，失败返回-1

示例函数 – 创建/打开

  1. mpd_t mq_open(const char* name, int oflag, mode_t, struct mq_attr* attr); – 创建

    1. name为队列名称，必须以斜杠开头
    2. oflag标志位，如O_CREAT | O_RDWR或O_NONBLOCK
    3. attr配置属性(结构体struct mq_attr)包含mq_maxmsg最大消息条数和mq_msgsize单条消息最大字节数，传NULL则使用系统默认值
    4. 返回值mqd_t是记录消息队列描述符的int数据类

  2. mqd_t mq_open(const char* name, int oflag); – 打开

示例函数 – 发送

  1. int mq_send(mqd_t mqdes, const char* msg_ptr, size_t msg_len, unsigned int msg_prio); – 无期限阻塞挂起

    1. msg_ptr指向要发送的消息数据的指针
    2. msg_len为消息的实际长度
    3. msg_prio为消息优先级，数字越大，优先级越高，内核会自动将高优先级的消息插入到队列前端。优先级相同按照先后顺序排列

  2. int mq_timedsend(mqd_t mqdes, const char* name, size_t msg_len, unsigned int msg_prio, const struct timespec* abs_timeout); – 超时控制(允许设置一个等待时间，超过设定时间后仍是满的，函数不再卡死，直接报错返回-1)

    1. const struct timespec* abs_timeout指定绝对时间超时点

示例函数 – 接收

  1. ssize_t mq_receive(mqd_t mqdes, char* msg_ptr, size_t msg_len, unsigned int* msg_prio); – 无期限阻塞挂起

    1. msg_ptr用于接收数据的缓冲区
    2. msg_len为缓冲区大小，必须大于等于队列设置的mq_msgsize，否则报错EMSGSIZE
    3. msg_prio传出参数，用于接收当前消息的优先级，不关心可传NULL
    4. 成功返回接收消息的字节数，失败返回-1

  2. ssize_t mq_timedreceive(mqd_t mqdes, char *msg_ptr, size_t msg_len, unsigned int *msg_prio, const struct timespec *abs_timeout); – 超时控制(允许设定一定最长等待时间，如果超过指定的时间依然没有接收到消息，函数自动解除阻塞，并返回-1)

示例函数 – 清理

mq_close(mqd_t mqdes);断开当前进程与消息队列的连接

mq_unlink(const char* name);从内核命名空间中彻底删除该消息队列

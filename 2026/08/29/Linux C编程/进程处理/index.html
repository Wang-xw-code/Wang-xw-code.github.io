进程

概念及分类

概念

是操作系统进行资源分配和调度的基本单位，包含一堆代码指令和数据的静态集合，进程为在内存中动态建立起来的全套资源集合体

孤儿进程与僵尸进程

  1. 孤儿进程：父进程先于子进程结束，此时自动被其祖先进程领养。危害在于脱离当前Shell终端的管理控制(难以关闭，若为死循环后台跑CPU)
  2. 僵尸进程：进程已经结束，用户态资源被释放，但内核中的进程描述符仍残留(父进程尚未调用wait/waitpid)。危害在于占用操作系统的PID数量(Linux默认为32768个)

struct task_struct进程描述符

结构体内容

存在于内核空间内存，记录了进程的所有身份信息，如

  1. pid_t pid;进程ID
  2. long state;进程状态：运行、休眠、僵尸
  3. struct mm_struct* mm;虚拟内存管理
  4. struct files_struct* files;文件描述符表
  5. sturct signal_struct* signal;信号处理
  6. struct task_struct __rcu* real_parent;进程树亲缘关系

内存映射表 struct mm_struct

进程有用一整套连续的虚拟地址空间，mm_struct结构体记录了该虚拟空间的核心区域

  1. Text段(代码段)：存放从磁盘加载进来的CPU机器指令。只读，多个相同程序进程共享
  2. Data段(数据段)：存放已初始化的全局变量和静态变量
  3. BSS段：存放未初始化或初始化为0的全局变量或静态变量，在磁盘空间中不占内存，启动时由内核清零
  4. Heap堆区：使用malloc()/new动态申请的内存，从低地址到高地址增长，由brk/mmap系统调用控制
  5. Memory Mapping Segment内存映射区：用来加载动态共享库或通过mmap映射文件
  6. Stack栈区：存放函数的局部变量、函数参数、返回地址。从高地址向低地址增长，自动分配与释放

文件描述符表struct files_struct

管理当前进程通过 open()、socket() 等打开的所有文件、网络连接和管道

struct signal_struct* signal

记录发给该进程的信号（如 SIGINT 键盘中断、SIGKILL 强杀、SIGSEGV 段错误），以及进程打算怎么处理这些信号

struct task_struct __rcu* real_parent

在内核建立的进程树中，记录父进程的 task_struct 内存地址

相关函数

getpid()

获取当前调用进程的PID

getppid()

获取当前调用进程的父进程PID

fork()创建进程

通过复制当前进程(父进程)创建一个全新的进程(子进程)；父进程的返回值寄存器RAX设置为子进程PID，子进程的返回值寄存器RAX设置为0；fork()刚完成时父子进程共享相同的物理内存页(子进程权限为只读)，只有当父子进程试图修改内存数据时，内核才为修改者复制一份私有的物理内存页，并将权限设置为可读可写(直接判定复制浪费时间与内存)

从fork之后，所有代码父子进程各自执行一次，可if判断pid分离父子进程代码或sleep()使其中进程休眠

waitpid()进程回收

在Linux中，一个进程退出释放进程代码段、数据段、用户栈、堆内存以及打开的文件描述符等大部分资源，但保留进程描述符(task_struct)，里面记录了进程的PID、终止状态、CPU使用时间等少量数据。每个操作系统能够分配的PID数量有限，若wait不及时清空占坑的task_struct，释放PID，当PID被耗尽时，系统无法创建新进程

pid_t waitpid(pid_t pid, int* wstatus, int options)

  1. pid指定回收目标
    1. pid > 0，指定PID，等待该进程，用于父进程精准等待某个特定任务完成
    2. pid == -1，等待任意一个子进程退出，常配合信号处理函数批量回收子进程
    3. pid == 0，等待以进程组ID为父进程的GPID的任意子进程，用于管理属于同一个进程组的子任务
    4. pid < 0，指定进程组ID
  2. wstatus获取退出状态，自声明int整数即可
  3. options控制行为模式
    1. 0默认阻塞模式，如果指定的子进程未结束，父进程会卡住挂起直到子进程退出
    2. WNOHANG非阻塞模式，如果指定的子进程未结束，waitpid立刻返回0，继续父进程代码
    3. ……

execve进程替换(已拥有程序)

概念

fork()增加新进程，如果新进程只跑父进程代码，功能受限，引出exec函数族。当调用exec时内核清空原进程的代码段、数据段、BSS段、堆和栈(mm_strcut映射)，将全新的可执行程序的mm_struct映射从磁盘装载进来，重新初始化该进程的地址空间，父子进程关系不变，打开的文件描述符默认保留下来(除非设置了FD_CLOEXEC标记)

函数示范 – execve第一个参数为路径

变与不变

  1. 变
    1. 所有的内存数据：局部变量、全局变量、堆内存、调用栈…
    2. 信号处理函数：冲掉原程序用signal()绑定的自定义C函数地址，将新程序的所有信号处理回复为系统默认动作
  2. 不变
    1. PID与PPID：进程的身份没有发生变化
    2. 信号忽略掩码：原进程忽略的信号，新进程继续忽略
    3. 文件描述符：新程序默认全盘继承原进程打开的文件描述符
  3. 如果想在转换进程时自动关闭文件描述符，在open文件时设置O_CLOEXEC标志

argv[]与envp[]

  1. argv[] – 命令行参数表
    1. 第一个参数固定是程序的名称/路径
    2. 第二/n个为执行的程序需要传入的参数
    3. 最后一个为NULL
  2. envp[] – 环境变量表
    1. 第一个参数为环境变量参数key = value
    2. 最后一个参数为NULL

exit(status)/_exit(status)进程退出

区别

exit(status) – 刷盘
  1. void exit(int status);（属于标准 C 库 <stdlib.h>）
  2. 调用exit(status)时，C库会按顺序完成以下步骤：
    1. 调用atexit()或on_exit()注册的所有清理函数（如释放全局对象、写入日志数据库）
    2. 刷新(Flush)并关闭所有打开的标准I/O流/缓冲区。卡在内存里没发出去的printf数据，会在这一刻强行发起write系统调用推给终端或文件
    3. 删除通过tmpfile()创建的所有临时文件
    4. 最终调用_exit(status)系统调用陷入内核，让内核彻底回收进程
  3. 适用于普通情况
_exit(status) – 不刷盘
  1. void _exit(int status); （属于 Linux 系统调用 <unistd.h>，在 POSIX 标准中也写作 _Exit）
  2. 调用_exit(status)时，进程会立刻“猝死”：
    1. 它完全不理会用户态的任何东西
    2. 不调用atexit()注册的任何函数
    3. 完全不冲刷标准I/O缓冲区！卡在缓冲区里的数据直接丢弃！
    4. 立刻执行系统调用陷入内核，内核强制把该进程在用户态的所有内存剥离
  3. 适用于fork()创建的子进程在execve失败后的返回

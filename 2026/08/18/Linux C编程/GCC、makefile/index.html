GCC

编译的整体流程

main.c -> “预处理” -> main.i -> “编译” -> main.s -> “汇编” -> main.o -> “链接” -> 应用程序

相关概念解释：

  1. 预处理

main.c -> main.i，操作为gcc -E -o main.i main.c生成展开后的纯C语言文本

处理所有以#开头的预处理指令(引入stdio.h)，删除所有注释，添加行号与文件名标识，会使文件体积膨胀
2. 编译

main.i -> main.s，操作为gcc -S -o main.s main.i生成对应架构的汇编指令文本

对预处理后的文本进行词法分析、语法分析等，将高层的C语言代码翻译成对应CPU架构(x86、ARM)的汇编指令

  1. 汇编

mian.s -> main.o，操作为gcc -c -o main.o main.s生成二进制目标文件(不可执行)

将汇编文本翻译成二进制机器码

  1. 链接

main.o -> main，操作为gcc -o main main.o生成完整的二进制可执行程序

将多个.o文件及依赖的静态库、动态库整合

常用的编译选项

  1. -E 预处理
  2. -c 把预处理、编译、汇编都做了，但是不链接
  3. -o 指定输出文件
  4. -I 指定头文件目录
  5. -L 指定链接时库文件目录
  6. -l 指定链接哪一个库文件

如：gcc -c -o b.o b.c表示只编译不链接，将b.c文件操作成b.o

缺点

.c->.o更改其中一个文件，其余不相关的也需要重新进行预处理、编译、汇编等过程

  2. 若存在文件则比较时间，如果依赖文件的时间比结果文件新，则需要重新执行该命令

相关语法

变量

  1. 即时变量：A := xxx，A的值即刻确定为xxx

  2. 延时变量：

    1. B = xxx，B的值使用到时才确定
    2. B ?= xxx，如果B是第一次定义才起效

  3. 变量使用：$(xxx)

通配符(%)

其中$^表示:左边所有的依赖；$@表示目标文件；$<表示第一个依赖文件

clean功能

伪目标(.PHONY: …)

普通目标若存在文件时需要根据时间进行判断，通过声明伪目标实现无条件执行后面的命令，常用于.PHONY: clean

函数

  1. $(foreach var, list, text) 遍历list列表中以空格分隔的每一个元素，依次赋值给临时变量var，然后对每个元素执行text中的处理，最后拼成一个新的字符串
  2. $(filter pattern..., text)在text中取出符合pattern格式的值
  3. $(filter-out pattern..., text)在text中取出不符合pattern格式的值
  4. $(wildcard pattern)根据pattern通配符去磁盘上查找，并返回实际上真实存在的文件名列表
  5. $(patsubst pattern, replacement, text)在text字符串中，寻找符合pattern的格式文件，并替换成replacement格式

CFLAG编译参数

gcc $(CFLAG) -c -o main.o main.c

常见问题

头文件””与<>区别

“”优先搜索当前源文件所在的目录，适用于用户自己编写的、项目内部的头文件

<>直接搜索系统的标准头文件库目录(如/usr/include)，适用于标准库头文件、系统API或第三方安装的库头文件

.h依赖的编译

实际巨额文件不确定某个文件具有哪些.h依赖，一个个查看效率低，可使用-MMD -MP和-include生成依赖文件，确保编译时囊括所有的.h依赖

交叉编译

概念及需求

在一个平台上编译的代码，通过交叉编译能够生成在另一个不同架构平台上运行的可执行程序或库文件。例如面对x86架构编译出来的程序无法被arm架构所识别。而嵌入式终端存储小，CPU效率低，默认不安装GCC等编译器及依赖头文件

格式

arm-buildroot-linux-gnueabihf-gcc为工具链前缀+gcc

常见交叉工具链前缀

  1. arm-linux-gnueabihf-适用于目标架构32位ARMv7
  2. aarch64-linux-gnu-适用于目标架构64为ARMv8/v9

实际场景

简单程序可直接通过命令行调用交叉编译器编译(arm-linux-gcc -o test test.c)，但企业级开源第三方库通常包含庞大的目录结构与复杂的依赖管理，必须使用自动化构建系统。常见为以下交叉编译方式

  1. 传统Autotools架构(包含configure脚本)

./configure --host=arm-buildroot-linux-gnueabihf --prefix=$PWD/tmp其中--host...-linux-指定目标运行环境为ARM；--prefix...指定产物安装路径

  1. CMake架构(包含CMakeLists.txt)

cmake -B buile -DCMAKE_C_COMPILER=arm-linux-gnueabihf-gcc -DCMAKE_CXX_COMPILER=arm-linux-gnueabihf-g++ -DCMAKE_INSTALL_PREFIX=$PWD/tmp

  1. ……

四种读取范式的相关结构体

struct input_event结构体 – 阻塞读取与非阻塞读取

概念

是Linux内核中专门用来描述和传输输入事件(内核用来抽象描述硬件设备产生的每一次操作的数据单元)的标准数据结构(定义在系统头文件<linux/input.h>中)。当键盘、鼠标或触摸屏等硬件或者其他玩意(这里只研究硬件)产生了动作，内核驱动就会把该动作打包成一个或多个struct input_event结构，存入/dev/input/eventX设备节点中

结构体源码定义

相关参数

  1. time记录内核捕获到该硬件动作时的精确系统时间，应用层可以用于计算双击间隔、手势滑动速度等
  2. type指定事件的大类，常见的值有
    1. EV_KEY (1)：按键/按钮事件(如键盘、鼠标左右键、触摸屏按下/抬起)
    2. EV_REL (2)：相对坐标事件(如鼠标移动、滚轮滚动)
    3. EV_ABS (3)：绝对坐标事件(触摸屏点击位置、游戏摇杆偏移)
    4. EV_SYN (0)：同步事件(相当于分隔符，表示以上这组事件打包发送完毕，可以更新UI了)
  3. code作用在于type大类下，精确标明具体的硬件标识如：
    1. type == EV_KEY：code可以是KEY_A、KEY_ENTER、BTN_LEF(鼠标左键)等
    2. type == EV_REL：code 可以是REL_X(X轴偏移)、REL_Y(Y轴偏移)
    3. type == EV_ABS：code 可以是ABS_X(绝对X坐标)、ABS_Y(绝对Y坐标)
  4. value记录动作的状态或动态变化值如：
    1. 按键事件(EV_KEY)下1为按下，0为松开，2为长按连发
    2. 相对坐标(EV_REL)下表示相对偏移量，如+5表示向右移5个像素，-3表示向上移3个像素
    3. 绝对坐标(EV_ABS)下表示触控点的物理坐标值，如X=1024，Y=768

struct pollfd fds结构体 – POLL/SELECT方式读取(多路复用I/O)

概念

定义在系统头文件<poll.h>中的底层通讯桥梁

pull函数 – 专门实现多路复用的核心系统调用函数

代码及相关参数

int pull(struct pollfd* fds, nfds_t nfds, int timeout);

  1. stuct pollfd* fds指向struct pollfd结构体数组的首地址，向内核提交一张”监控清单”，将想要同时监控的设备信息一次性传给内核
  2. nfds_t nfds告诉内核fds数组里有多少个struct pollfd结构体元素
  3. int timeout为超时休眠时间，控制当没有数据可读时，poll()函数在内核里的休眠阻塞行为，以下为三种不同取值的含义
    1. timeout == -1，无限期休眠阻塞，如果没有硬件数据产生，poll()会让当前线程永远休眠挂起，CPU占用率为0%，直到有硬件动作唤醒
    2. timeout == 0急速查询，内核查看设备缓冲区有没有数据，不管有没有立即返回
    3. timeout == x定时休眠，如果在x毫秒内硬件有动作，提前唤醒返回，如果满x毫秒无硬件动作，poll()强制唤醒并返回0

poll()函数返回值含义

poll()执行完毕会返回int类型整数。当返回值>0表示成功，代表监控的设备中，共有多少个设备产生了事件；当返回值==0表示超时，代表在指定的timeout毫秒时间内，没有任何设备产生了数据；当返回值==-1表示系统调用出错，代表poll()本身执行失败，例如被系统外部信号打断，此时errno会被设为EINTR

结构体源码定义

相关参数

  1. events常用状态掩码及作用
    1. POLLIN (0x0001)：普通可读事件。告诉内核：“这个设备如果有新数据可以读了（比如键盘被按下了、网卡收到了数据包），立刻通知我。”
    2. POLLOUT (0x0004)：可写事件。告诉内核：“如果这个设备的发送缓冲区空出来了、可以写入数据了，通知我。”
    3. POLLPRI (0x0002)：带外高优先级数据可读（硬件产生极其紧急的中断信号时使用）
  2. revents在调用poll()之前，字段内容毫无意义(系统调用时内核会抹掉清零)。revents是内核专属的写字板，当内核被硬件唤醒后，内核会扫描硬件状态，将请求的掩码和硬件实际状态做比对，然后把结果写入revents。比如events中未设置POLLERR(硬件损坏)等请求，内核只要检测到了，会强制写入revents中，避免程序误以为设备还未发送数据，持续调用read()，导致程序崩溃卡死或抛出段错误等

四种I/O读取范式

读取前的操作

正式读取动态事件之前，"通常"需要通过ioctl命令获取设备自身的静态身份信息以及支持的操作集合，ioctl中EVIOCGNAME获取设备名称，EVIOCGID获取设备ID…，获取到设备的名称或支持的操作等

休眠唤醒模式(阻塞IO) – read默认阻塞

概念

默认以open(path, O_RDWR)打开，若设备无数据，进程放入内核等待队列，状态转为TASK_INTERRUPTIBLE进入休眠，CPU占用率为0%。硬件产生中断后，内核唤醒进程并获取数据给应用层

阻塞底层逻辑

阻塞并非由while循环所造成，当程序运行到ssize_t bytes = read(fd, &ev, sizeof(ev))时，应用层调用read()，CPU被内核所控制，此时若/dev/input/event0硬件缓冲区中没有数据，则内核将进程挂起(暂停运行)，并放入设备的休眠等待队列中，但此时read()函数并未返回，只有当硬件受到操作产生中断，内核接收到数据，才会将进程唤醒，内核对数据进行拷贝，read()函数返回

while循环读取

能够持续监控硬件的相关操作，例如手机电源键，系统后台存在一个专门监听按键的线程，当手机黑屏待机时线程卡在read()阻塞休眠，CPU占用率为0%，按下电源键产生硬件中断，read()被唤醒返回一个struct input_event，线程读取到该事件时点亮屏幕，渲染锁屏界面，处理完亮屏后循环重新进入下一次while，再次卡在read()阻塞休眠，等待下一次按动电源键

阻塞读取必要性

该线程任务单一，如果没有任何事件发生，该线程必须彻底进入休眠，把100%的CPU算力和电量留给前台运行的应用程序，比如电脑关机操作

查询模式(非阻塞IO)

概念

以open(path, O_RDWR | O_NONBLOCK)打开，调用read时，若有数据则立即返回，若无数据，内核不休眠，立即返回-1，并设置errno = EAGAIN

休眠函数的必要性

非阻塞读取不会使进程休眠，在进行完一次查询后进入第二次while循环时，又重新查询，假如while里的总操作用时少，CPU会一直浪费在非阻塞查询上，使用休眠函数(usleep)能够设置间隔时间

非阻塞读取的必要性

常用于在查询完状态顺便进行其他操作，比如ATM机查询是否通过设备输入密码，若没有则顺便进行30秒倒计时以及防诈视频播放等操作，这是阻塞查询所无法实现的。当然while循环可以记录上一次循环中比如播放视频的帧数，下一次接上，避免掉帧等问题，倒计时也类似，可以while循环外设置初值，当while内消耗掉后通过if判断进行其他操作(打印输入超时，即将退回主界面等)

POLL/SELECT方式读取(多路复用I/O)

概念

应用层主线程主动调用poll()或select()，主线程在poll()处休眠等待，直到内核通知至少有一个设备有数据可读，主线程被唤醒，随后主动遍历各个文件描述符，找出有数据的设备并调用read()。适用于同时监控多个输出设备(例如同时监听键盘和触摸屏)

异步通知方式读取(FASYNC/SIGIO信号驱动)

概念

应用层不需要调用poll()去看守，主线程正常跑自己的死循环或业务逻辑。当设备有数据到来时，内核驱动主动向该进程发送SIGIO信号，强行打断主线程，跳转去执行注册好的信号处理函数，在处理函数中调用read()

建立异步通知的三部曲

  1. 注册信号handler:signal(SIGIO, sig_handler);
  2. 指定接收信号的属主进程:fcntl(fd, F_SETOWN, getpid());
  3. 使能驱动异步通知:fcntl(fd, F_SETFL, flags | FASYNC);
